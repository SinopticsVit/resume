# Шпаргалка: спецдеп / ЭДО / регуляторика (уровень собеседования)

## 1. Кто есть кто

```
Эмитент ──реестр──► Регистратор
Клиент/брокер ──счета депо──► Депозитарий ◄──► НРД (инфраструктура)
УК / НПФ / фонд ──имущество фонда──► Специализированный депозитарий (контроль + учёт)
```

- **Депозитарий** — учёт прав на ЦБ клиентов (счета депо), операции по поручениям.
- **Спецдепозитарий (СД)** — для коллективных инвестиций: учёт/хранение имущества фонда + **контроль** операций и состава/структуры активов (чтобы УК не нарушила правила фонда и закон).
- **Регистратор** — реестр владельцев ЦБ конкретного эмитента.
- **УК** — управляет активами фонда в рамках ПДУ/правил.
- **НРД** — ключевая инфраструктура рынка; часто канал ЭДО.
- **ВТБ СД** — крупный СД группы ВТБ; свой программно-технический комплекс учёта и **СЭД**.

## 2. Что делает система «спецдеп + ЭДО» (глазами СА)

Типовой поток:

1. Контрагент (УК и др.) присылает **электронный документ** (поручение / отчёт / сообщение).
2. Проверки: формат (XML/XSD), подпись (УКЭП), права/роль, бизнес-правила.
3. Документ получает **статус** (принят / на проверке / исполнен / отказ).
4. При успехе — отражение в **учёте/контроле** (операция, актив, ограничение).
5. Наружу — **квитанция / отказ / исходящий ЭД**.
6. Всё пишется в **аудит** (кто, когда, что, на основании какого ЭД).

Ваши аналогии из опыта: Sinoptics (валидация документа, статусы, эскалация) + платёжный контроль в корпфинансах.

## 3. Термины — 30 секунд каждый

| Термин | Смысл |
|--------|--------|
| Счёт депо | Счёт учёта ЦБ в депозитарии |
| Пай / ПИФ / ЗПИФ | Доля в фонде / типы фондов |
| ПДУ | Правила доверительного управления |
| СЧА | Стоимость чистых активов |
| Контроль состава/структуры | Проверка, что активы фонда соответствуют ограничениям |
| Поручение | ЭД-распоряжение на операцию |
| Квитанция | Служебный ответ об приёме/результате |
| Формализованный ЭД | Жёсткая схема полей (XSD и т.п.) |
| Неформализованный | Свободный документ (письмо, скан) в контуре ЭДО |
| УКЭП | Усиленная квалифицированная ЭП — юр. значимость |
| ОДК / СЭД ОДК | Контур/система ЭДО (в т.ч. у ВТБ СД) |
| НРД «Луч» | Известная СЭД/ПО для участников рынка |
| XBRL | Машиночитаемая отчётность (часто в регуляторке) |

## 4. Законы — что можно сказать без блефа

**39-ФЗ** — базовый закон о рынке ЦБ: кто участник, какие виды деятельности, общие рамки учёта и раскрытия.  
**115-ФЗ** — ПОД/ФТ: клиент, проверки, признаки подозрительности, ограничения — в ИС это правила, стоп-факторы, эскалация compliance.  
**Нормативка ЦБ** — детализирует учёт, контроль, отчётность, ЭДО.  
**Внутренний регламент СД / правила ЭДО** — то, из чего СА чаще всего делает ТЗ.

Формула: *норма → бизнес-правило → проверка в процессе → поле/статус/событие в системе → тест*.

## 5. REST vs SOAP vs файл (для их контура)

| Способ | Когда типично | На что смотрит СА |
|--------|----------------|-------------------|
| REST+JSON | Новые сервисы, ЛК, внутренние API | OpenAPI, коды, идемпотентность |
| SOAP+XML | Легаси, строгие контуры, часть фин/гос | WSDL, XSD, faults |
| Файл / шина ЭДО | Массовый обмен ЭД, операторы/НРД | Имя файла, схема, подпись, повтор, квитанции |

## 6. Мини-сценарий «рассказать у доски»

**Название:** Приём поручения УК на операцию с активом фонда.

**Статусы:** `RECEIVED` → `FORMAT_OK` → `SIGNATURE_OK` → `BUSINESS_CHECK` → `POSTED` / `REJECTED` → `RECEIPT_SENT`.

**Ошибки:** неверная схема; просроченная подпись; операция запрещена контролем; дубликат message_id; таймаут учёта.

**Сущности:** `ElectronicDocument`, `Counterparty`, `Fund`, `Asset`, `Operation`, `ControlResult`, `Receipt`.

**Приёмка (примеры):**
- дубликат поручения не проводит операцию дважды;
- отказ содержит код и человекочитаемую причину;
- каждое изменение статуса пишется в audit log;
- при недоступности учёта документ не теряется (retry / ручной разбор).

## 8. Фразы, которые звучат senior

- «Сначала зафиксируем инварианты: что нельзя нарушить даже при сбое».  
- «Нужен корреляционный id от ЭД до проводки/операции».  
- «Отказ — тоже контракт: код, причина, можно ли повторить».  
- «Контроль спецдепа — отдельный доменный слой правил, не только “сохранить документ”».  
- «Домен закрою с методологом; метод анализа у меня уже боевой».
